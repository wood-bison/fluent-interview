# Полный scroll‑sweep внутренних маршрутов — 3 сентября 2026

## Как запускалось

Приложение поднято штатной командой из umbrella‑корня:

```text
pnpm run dev
```

Веб‑клиент доступен на `http://localhost:47350/`; target остаётся на `main`
commit `abad4585c8489a1cebf5edb3bf7443421c581e60`. Проверка выполнялась
read-only в подключённом браузере. Эксперименты, learner submissions,
AI-запросы и owner inputs не трогались.

## Результат

Из одиннадцати основных экранов собраны все same-origin ссылки, включая
questions, lessons, lab, preview, projects и Studio hand-offs. Получено
**162 уникальных маршрута**.

Для каждого маршрута проверялись:

1. наличие `.fel-main` или semantic `<main>`;
2. корректная высота и `scrollHeight`;
3. принудительный переход `scrollTop = 0 → maxScroll`;
4. достижение нижней границы контейнера (допуск округления браузера ≤ 1 px).

Итоги:

- **162/162** маршрута имеют основной контентный контейнер;
- **0** маршрутов без `main` или с ошибкой навигации;
- **89** маршрутов имеют вертикальный overflow;
- **89/89** длинных маршрутов достигают низа контейнера (все реальные
  failures — 0);
- **73** коротких маршрута полностью помещаются в viewport и overflow не
  требуют.

`body { overflow: hidden }` не является дефектом сам по себе: scroll ownership
находится у `.fel-main`, что подтверждено изменением `scrollTop` на странице
вопросов и повторным sweep по всем ссылкам. Это предотвращает двойной scroll
у shell и оставляет header/sidebar фиксированными.

## Ограничения

Sweep доказывает работу DOM scroll‑контейнеров и маршрутов в текущем desktop
viewport. Он не заменяет человеческую проверку трекпада/колеса, VoiceOver,
визуального сравнения на реальном Studio Display и owner acceptance G10S‑246.

G10S‑246 остаётся fail‑closed: reviewed packet head `008703c…` старше
текущего `main` `abad458…`, поэтому G11 breadth, serving и release pointer не
продвигаются автоматически. Старые репозитории, Docker containers/volumes,
кэши и данные не удалялись.
