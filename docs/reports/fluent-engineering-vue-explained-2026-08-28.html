01 · Короткий ответ

UI
Vue‑репозиторий = весь браузерный интерфейс платформы.

Название fluent-engineering-vue описывает технологию реализации, а не новый учебный трек. Пользователь по‑прежнему работает с Fluent Engineering Lab; просто текущая web‑поверхность теперь собрана на Vue 3.

Если на экране есть программа, путь Node.js или Java, Atlas, вопросы, конспект, редактор, терминал, прогресс или AI‑панель — это поверхность Vue. Vue не становится владельцем самих данных: он показывает согласованные ответы сервисов и отправляет пользовательские действия.

05 · Как один пользовательский запрос проходит систему

Например, вы открываете задачу Node.js. Vue отвечает за экран, но результат появляется только после согласованного пути данных.

01 · INTENT
ПользовательОткрывает путь или нажимает Run.
02 · UI
Vue viewМаршрутизирует действие и показывает pending/error state.
03 · API
LabВозвращает released projection и проверяет права/связи.
04 · SOURCE
Brain / RuntimeBrain даёт content, Runtime исполняет revision.
05 · EVIDENCE
Vue renderZod проверяет payload; UI показывает trace и следующий шаг.

Идентичность не теряется: route → question → capability/family → exact revision → attempt.

06 · Что именно внутри Vue‑репозитория

apps/web

Vue Router views, app shell, навигация, canvas/graph, editor, terminal и AI companion.

packages/contracts

Zod‑схемы ingress/egress. Внешний payload сначала парсится, потом доходит до компонента.

packages/api-client

Типизированный fetch‑адаптер и единая error boundary для API‑запросов.

packages/design-tokens

Семантические токены светлой/тёмной темы и CSS‑first тема для Tailwind.

packages/ui

Доступные primitives и SVG‑иконки. Vendor‑компоненты скрыты за нашими обёртками.

State model

TanStack Vue Query хранит server state; Pinia — только UI/session preferences и workflow state.

Практический смысл. Если вы видите в интерфейсе «Java», «Node.js» или «Questions», это не отдельные приложения и не отдельные базы внутри Vue. Это экраны, которые получают опубликованные данные через API‑контракты.

07 · Что произошло со старым Angular

Angular был предыдущей реализацией браузерного shell. В текущей архитектуре в качестве learner/operator web‑клиента закреплён Vue. Поэтому обычный запуск больше не поднимает два фронтенда и не требует синхронизировать Angular с Vue.

Важно различать две вещи

  • Продукт остался тем же:  Fluent Engineering Lab, его пути, задачи, вопросы и runtime‑связи не должны исчезать из‑за смены UI‑стека.
  • Реализация UI изменилась:  текущие экраны рендерит Vue 3. Если экран или вкладка потерялись при переносе, это defect паритета Vue, а не «новая концепция продукта».
  • Старый Angular не является вторым активным клиентом:  его нельзя случайно вернуть в launcher как параллельный источник интерфейса.

08 · Где работать с изменениями

  1. Меняем внешний вид или interaction

    Работаем в fluent-engineering-vue. Проверяем light/dark, keyboard, desktop‑профили и route E2E.

  2. Меняем смысл данных

    Сначала определяем владельца: Lab, Brain или Runtime. Затем меняем versioned contract и его consumer tests.

  3. Запускаем всё вместе

    Команду выполняем из корня fluent-interview, чтобы не получить «красивый UI» без реальных API.

Команды

# Полный dev‑stack
cd /Users/sergeyzhechko/developer/fluent-interview
pnpm run dev

# Только изолированный Vite loop для UI‑работы
cd /Users/sergeyzhechko/developer/fluent-interview/fluent-engineering-vue
pnpm install --frozen-lockfile
pnpm dev

# Проверка Vue‑пакета
pnpm check
pnpm e2e

Изолированный Vite loop удобен для вёрстки, но API‑зависимые экраны корректно проверяются только в полном workspace‑запуске.

11 · Частые вопросы

Это отдельное приложение или часть Fluent Lab?

Технически — отдельный web‑репозиторий. Продуктово — часть Fluent Engineering Lab. Такой раздел нужен для независимого владения UI и чистых границ, но launcher и пользовательский сценарий остаются едиными.

Почему нельзя хранить всё в одном репозитории?

Можно было бы, но сейчас workspace сознательно устроен как polyrepo umbrella: Brain, Runtime, Lab и UI имеют разные release‑циклы и владельцев. Объединение — отдельное архитектурное решение, а не условие для работы Vue.

Если во Vue нет старой вкладки, значит её отменили?

Нет. Старая функциональность должна быть либо перенесена, либо явно отмечена как parity‑gap. Смена Angular на Vue не должна менять учебную модель и не освобождает нас от проверки маршрутов, вопросов и runtime.

Куда писать, если нужно добавить новый вопрос?

В Question Brain через content workflow и release. Во Vue добавляется только отображение или interaction, если для новой модели данных нужен UI. Браузер не должен создавать канонические карточки сам.

Что означает local-only у Vue?

У дочернего Git‑репозитория есть локальная история и pinned revision, но в workspace‑метаданных не указан настоящий remote. Поэтому строгий production‑provenance gate ещё не закрыт, хотя локальная разработка и проверки могут работать.
